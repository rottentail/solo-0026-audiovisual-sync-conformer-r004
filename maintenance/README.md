# Version Maintenance Admission

This directory holds the durable materials used to decide whether a candidate
build of the Audiovisual Sync Conformer may be released. The service treats
take descriptors (音画描述), sync readings (同步读数), and review-bundle
receipts (审片包回执) as continuously usable delivery records. A version is
therefore **not** admitted because the binary builds and `/healthz` answers,
and it is also not rejected merely because some output bytes differ. Admission
is decided by replaying a committed media corpus and comparing the *meaning*
of the records the candidate produces against the records the last admitted
version produced.

The gate command is `cmd/syncversiongate`. It adds no production behavior; it
drives the real HTTP routes and media packages of the tree it is built from.

## The corpus

`corpus/` is the contract. It is committed, version-independent media plus the
records the admitted version produced from it:

```text
corpus/
├── corpus.json            # take list, analysis policies, correction ceilings
├── inputs/                # the actual WAV/Y4M materials (actual素材)
└── golden/
    ├── records.json       # golden delivery records, split by comparison level
    └── bundles/           # review bundles generated by the admitted version
```

The seven takes and the readings the admitted baseline produces:

| take | material | expected reading |
|---|---|---|
| `calibration-125` | 48 kHz mono, flash frame 9 | events 500/375 ms, offset +125 ms, applied 6000 samples |
| `negative-drift` | audio early | offset −80 ms, applied −3840 samples |
| `stereo-44k1` | 44.1 kHz stereo | offset +117 ms, applied 5160 sample frames (rounding matters) |
| `ramp-flash` | flash rises over frames 9→10 | detector picks frame 9: offset +75 ms |
| `weak-flash` | 60-unit luma delta | confidence 0.875, near the 0.55 policy |
| `silent-flat` | silence, flat luma | analysis `failed/sync_detection_failed`, conform refused `analysis_not_ready` |
| `beyond-ceiling` | offset +417 ms | conform `failed/correction_limit_exceeded`, no bundle route |

## Comparison levels

Every compared field belongs to exactly one level, and `golden/records.json`
stores the fields under those headings so reviews see the classification in
the file itself.

**Semantic — a difference means the candidate changed the meaning of existing
results. Verdict: REJECT.**

- take descriptors: state, sample rate, channels, bit depth, frame counts,
  durations, peak/RMS dBFS, geometry, frame rate, chroma;
- sync readings: terminal state, error code, audio/picture event times,
  signed offset, drift PPM, and the policy the decision used;
- conform records: existence, terminal state, error code, measured/applied
  offsets, applied samples, correction ceiling, bundle availability;
- bundle content decoded: aligned audio *samples* and conformed video
  *frames* (stored as content hashes), receipt semantic fields, entry set;
- the delivery chain, checked on every bundle, old and new: record digests ↔
  bundle bytes ↔ receipt digests ↔ admitted-take digest must agree, and the
  aligned pair inside the bundle must still measure within ±2 ms of zero.

**Advisory — readings moved but no decision, offset, or state changed.
Verdict: ADMIT WITH SIGN-OFF.**

- confidence, audio prominence, video prominence.

**Byte — container bytes and digests. Never blocks admission.**

- payload digests and byte counts, output digests, bundle digest/byte count,
  receipt digest fields. Byte drift with equal decoded content is
  audiovisual-equivalent (字节变化但音画等价). Note that the receipt embeds a
  creation timestamp, so even re-running the *same* build shows bundle-digest
  drift; byte equality is not a usable gate in either direction.

## Two directions of judgment

1. **Forward replay.** The corpus inputs are admitted, analyzed, and
   conformed again by the candidate, and the records are compared as above.
2. **Historical bundle re-interpretation.** Each committed golden bundle —
   produced by the previously admitted version — is reopened and its aligned
   pair is re-measured with the *candidate* detector. If the residual offset
   leaves the ±2 ms band, then receipts already delivered ("this bundle is
   conformed") no longer mean what they meant, even though every file is
   still perfectly readable (文件仍可读却同步语义已经变化). This is a
   semantic failure and blocks release.

## Admission procedure

Run from the **candidate** checkout — the gate exercises the build it is
compiled from, and the corpus travels with the repository:

```bash
go build ./...
go run ./cmd/syncflowcheck -workflow admit-take
go run ./cmd/syncflowcheck -workflow analyze-sync
go run ./cmd/syncflowcheck -workflow render-conform
go run ./cmd/syncversiongate -report gate-report.json verify
```

Exit codes: `0` admit, `2` admit with sign-off, `1` reject. (`go run` maps
non-zero child exits to 1; use a built binary when the exact code matters.)
Attach `gate-report.json` to the release review and record the outcome in
`ADMISSION_LOG.md`.

## Release trade-offs (发布取舍)

- **REJECT with an intentional semantic change** (e.g. a deliberately better
  detector): do not ship silently. Ship it as a recorded semantic release:
  attach the gate report to the release notes, re-bless the corpus in the
  same commit (`capture -force`, reviewed through the `records.json` diff),
  and decide the disposition of historical receipts — re-issue affected
  bundles or annotate them as measured under the previous detector. If
  detector semantics are expected to evolve, version the detector in the
  receipt; the `event-detector-policy` extension seam in `.task-source.json`
  is the recorded anchor for that work.
- **ADMIT WITH SIGN-OFF**: release is allowed when a named reviewer accepts
  the advisory drift in the log. Re-bless the golden records afterwards so
  the next candidate compares against the new baseline, not against a
  superseded one.
- **Byte drift only**: no action. The decoded content is identical.

## Maintaining the corpus

- Add a take by extending `corpusSpecs` in `cmd/syncversiongate/main.go`,
  then `generate -force` (rewrites `inputs/` and `corpus.json`) and
  `capture -force` (re-blesses `golden/`). Review the change through
  `corpus.json` and `golden/records.json`; never hand-edit golden files.
- `capture` refuses to bless a build that fails its own delivery-chain
  checks, and rewrites every bundle (receipt timestamps make bundles
  per-run artifacts; `records.json` is the review surface).
- `verify` binds inputs to golden records by digest, so editing inputs
  without re-capturing fails loudly.

## Demonstrated this round

Three candidate variants were built in throwaway copies of this tree and
judged against the committed corpus. All three passed `go build` and all
three production workflow checks — including variant B, whose detector
change the calibration pair cannot see.

| candidate | change | gate verdict |
|---|---|---|
| baseline self-check | — | `ADMIT` (exit 0); only per-run bundle-digest byte drift |
| A: codec byte variant | WAV encoder emits 18-byte `fmt ` chunk; Y4M frames carry a comment token | `ADMIT` (exit 0): 30 byte-level differences, decoded samples/frames identical |
| B: detector variant | flash threshold 0.55 → 0.80 | `REJECT` (exit 1): `ramp-flash` event 375→416 ms, offset 75→34 ms, applied 3600→1632 samples; historical bundle re-measures at −41 ms |
| C: prominence variant | video prominence scale ÷80 → ÷120 | `ADMIT WITH SIGN-OFF` (exit 2): `weak-flash` confidence 0.875→0.75 |

## Known boundaries

- Delivery records quantize to whole milliseconds; detector drift smaller
  than 1 ms is invisible in the records (applied samples derive from the
  millisecond offset). Byte-level audio comparison of bundles shares that
  limit.
- Error *messages* are prose and are not compared; error *codes* are the
  contract.
- The corpus covers the baseline media boundary: 16-bit PCM WAV and
  progressive planar C420 Y4M. New formats need new corpus takes.
